## 1. Deterministic Recommendation Engine

### Objective
Transform factual evidence (`ExtractedEvidence`) into prioritized, step-by-step remediation action items without introducing unbacked LLM hallucinations.

### Rule-Based Remediation Matrix

| Observed Fact / Gap | Priority | Action Item Title | Prescribed Remediation Guide |
| :--- | :---: | :--- | :--- |
| `mentioned == False` | **P0 (Critical)** | Create Category Landing Page | Publish a dedicated `/solutions/<category>` page with explicit schema markup detailing core value propositions. |
| `raw_citations == []` AND `mentioned == True` | **P1 (High)** | Build Citation Ingress | Submit product listing updates to top cited third-party platforms (G2, Capterra, Trustpilot) to anchor domain citations. |
| `matched_snippets` missing competitor comparison | **P1 (High)** | Publish Versus Comparison Page | Create an explicit `/vs/<top-competitor>` comparison page highlighting feature matrix differentiators. |
| `competitor_count > 3` | **P2 (Medium)** | Optimize Positioning Copy | Update homepage H1/H2 meta tags to use specific, long-tail category keywords rather than generic terms. |

## 2. Prompt Evaluation System

### A. Multiple Prompts per Provider
To eliminate single-prompt bias, the system dispatches 3 canonical query variations per audit:
1. **Direct Recommendation Prompt**: `"What are the top software solutions for <category>?"`
2. **Comparative Prompt**: `"Which software tools are best compared to <competitor> for <category>?"`
3. **Use-Case Prompt**: `"What software should a team use for <specific-use-case>?"`

### B. Prompt Versioning & Storage Schema
- Prompts are registered in version control with explicit IDs: `PROMPT_CATEGORY_DIRECT_V1.2`.
- Every `ProviderResult` stores `prompt_id` and `prompt_version` alongside raw response text for 100% audit reproducibility.

## 3. Evaluation Dataset & Benchmark Suite

### A. Gold-Standard Evaluation Corpus
- **Dataset Size**: 100 human-annotated ground truth audit reports across 10 SaaS categories (CRM, ERP, DevOps, Marketing, Security, Finance, HR, Analytics, Collaboration, Design).
- **Manual Verification Process**: 2 independent human annotators manually inspect raw AI model outputs, marking true brand mentions, true citation URLs, and competitor brands.

### B. Precision & Recall Metrics
- **Brand Mention Precision Target**: **> 98%** (minimizing false positive brand mentions).
- **Brand Mention Recall Target**: **> 95%** (ensuring actual mentions are caught).
- **Citation Extraction Accuracy**: **> 99%** (regex URL extraction verification).

---

## 4. Confidence & Uncertainty Framework

To prevent customer distrust caused by LLM non-determinism, the platform explicitly communicates uncertainty:

1. **Sampling Consistency Metric**: Evaluates agreement across 3 prompt variations (e.g. `3/3 Prompts Recommended` = **High Consistency**, `1/3 Prompts Recommended` = **Low Consistency / High Variance**).
2. **Explicit Variance Badging**: Displays a `"Low Consistency Alert"` on reports when AI responses vary significantly across prompt variations.
3. **Timestamped Evidence Chain**: Every report explicitly displays: *"Evidence extracted from live model response at <UTC timestamp>."*

## 5. Closed-Loop Verification Workflow

How customers confirm that published fixes actually updated AI recommendations:

```text
Step 1: Customer receives AI Report indicating Omitted status.
   │
   ▼
Step 2: Customer executes prescribed Action Item (e.g. publishes /vs-competitor page).
   │
   ▼
Step 3: Customer clicks "Mark Fix Implemented & Schedule Verification".
   │
   ▼
Step 4: System sets a 14-day automatic re-audit timer (allowing LLMs to re-crawl web).
   │
   ▼
Step 5: System executes automated re-audit on Day 14.
   │
   ├── IF mentioned == True  ──> "Fix Verified! Brand is now Recommended in AI Output."
   └── IF mentioned == False ──> "Fix Unverified. Action item escalation recommended."
```

## 6. Product Analytics Event Schema

The platform tracks 6 core product events for telemetry and conversion optimization:

1. `audit_requested`: Triggered when user submits website URL.
2. `audit_completed`: Triggered when backend completes job execution.
3. `report_viewed`: Triggered when user opens the report dashboard view.
4. `evidence_quote_expanded`: Triggered when user opens raw evidence drawer.
5. `action_item_clicked`: Triggered when user clicks a prescribed remediation guide.
6. `verification_scheduled`: Triggered when user schedules a 14-day fix verification.

---

## 7. Product KPIs (North Star Metrics)

1. **Audit Completion Rate**: **> 95%** of launched audits complete successfully in < 30 seconds.
2. **Action Item Engagement Rate**: **> 40%** of report viewers click at least one remediation guide.
3. **30-Day Fix Verification Rate**: **> 30%** of users who implement fixes verify an updated AI recommendation within 30 days.
4. **Report Repeat Return Rate**: **> 50%** of users re-visit their audit report within 14 days.
